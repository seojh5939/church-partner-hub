## 📌 개요 및 핵심 목표
1. **이원화된 운영 모드 (Dual-Track Schema & Mode)**:
   - **마스터 관리 모드 (내부 기획자용)**: 17개 고유 헤더 컬럼 100% 보존, 제안사업/후속조치/교세 종합 관리, 옵시디언 동기화.
   - **간편 주소록 모드 (외부/일반 사용자용)**: 단순 입력 `[담임목사, 지역, 교회명]` 3개만으로 정제된 `[주소록 + 공식 홈페이지]` 자동 생성 및 간이 엑셀/CSV 내보내기.
2. **2단계 주소·홈페이지 연계 Grounding 및 종속적 불확실성(Cascading Uncertainty)**:
   - 1차 도로명 주소 추정 ➡️ 2차 주소 기반 홈페이지 교차 대조.
   - **핵심 원칙**: 1차 교회 주소가 불확실(`Low`/미확정)한 경우, 해당 주소 기반으로 탐색된 홈페이지 역시 **당연히 '불확실(Uncertain / 검증 보류)'** 처리하여 오정보 완전 차단.
3. **지역별 교세·교단·규모 분석(소형/중형/중대형/대형/초대형 및 교단 분포, 개수, 점유율, 드릴다운)**
4. 회사 요구 시 신속한 대응을 위한 **공문/선물 발송 퀵서처(원클릭 복사)**
5. 개인용 **옵시디언 스마트 동기화(Diff 대조, 상호보완)**
6. 윈도우 환경 무설치 **단일 포터블 `.exe` (PyInstaller + pywebview)**

## 🛠️ 개발 구현 원칙 (Core Engineering Principles)

1. **S.O.L.I.D 객체지향 설계 원칙 철저 준수**:
   - **SRP (단일 책임)**: 엑셀 입출력(`ExcelEngine`), 주소 탐색(`AddressGrounder`), 홈페이지 검증(`HomepageGrounder`), 통계 분석(`AnalyticsEngine`), 퀵서치(`DispatchManager`) 등 각 모듈의 책임을 철저히 분리.
   - **OCP (개방-폐쇄)**: 검색 공급자(지도/웹) 및 내보내기 포맷 확장은 전략(Strategy) 인터페이스를 통해 기존 코드 수정 없이 확장 가능하도록 구성.
   - **LSP (리스코프 치환)**: 단위 테스트용 Mock 객체와 실제 구현체가 동일한 데이터 계약(Dataclass)을 준수하여 상호 대체 가능성 보장.
   - **ISP (인터페이스 분리)**: 간편 주소록 모드와 마스터 모드에 불필요한 의존성을 강제하지 않고 모듈별 특화 인터페이스 제공.
   - **DIP (의존 역전)**: IPC 브릿지 및 상위 로직이 저수준 크롤러/파일 IO 구현체에 직접 결합되지 않고 추상화에 의존.

2. **YAGNI (You Aren't Gonna Need It) 원칙 준수**:
   - **"지금 당장 필요한 기능만 고려하여 작성하기"**: 미래에 필요할지도 모른다는 추측에 기반한 미사용 파라미터, 복잡한 플러그인 아키텍처, 거대한 프레임워크성 추상화를 사전에 구현하지 않음.
   - 현재 확정된 요구사항(2단계 주소·홈페이지 연계 Grounding, 2대 운영 모드, 5단계 교세, 퀵서치, 옵시디언 동기화)을 만족하는 가장 명확하고 간결한 코드(KISS) 작성.

3. **실용적 확장성 (Pragmatic Extensibility - 2~3회 변경 대응 버퍼)**:
   - **"2~3회 정도의 수정/요구사항 변경이 들어오는 것에 무리 없이 대응할 수 있는 수준까지만 설계하기"**:
   - 무한한 확장성을 추구하는 과잉 엔지니어링(Over-engineering)을 엄격히 배제.
   - 엑셀 컬럼 1~2개 추가/순서 변경, 웹 스크래핑 HTML 셀렉터 변경, 신뢰도 임계값 조정 등 실무에서 2~3회 반복되는 일상적 변경에 유연하게 대처할 수 있는 매개변수 구조화 및 모듈 분리 수준까지만 설계.

  - 엑셀 파일 락 충돌 방지(임시 파일 원자적 교체 및 파일 열림 사전 감지)
- [ ] `DispatchManager` 구현 (`src/core/dispatch.py`):
  - 교회명 초성 검색(`ㄱㅈㅅ` ➡️ 광주겨자씨교회) 및 목회자명 필터
  - 공문용 규격 텍스트 / 택배 선물용 규격 텍스트 / 스프레드시트용 TSV 원클릭 클립보드 복사
  - 선택 교회 일괄 발송용 미니 엑셀 다운로드

### Phase 3: 2단계 하이브리드 주소·홈페이지 추정기 & 대화형 Grounding 검증 UI
- [ ] `AddressGrounder` 구현 (`src/core/grounder.py`):
  - 1차: 무설정 웹 탐색(네이버 플레이스/포털)으로 도로명 주소 및 목회자 일치 스니펫 수집
  - 2차: `.env` 또는 설정에 카카오/네이버 API 등록 시 공식 API 고속 자동 전환
  - 신뢰도(Confidence) 산출: High (90%+), Medium (70~89%), Low (<70%)
- [ ] `HomepageGrounder` 구현 (`src/core/homepage_grounder.py`):
  - 포털 웹 검색을 통한 공식 웹사이트 수집 및 '오시는 길'/푸터 주소 파싱
  - **Cascading Uncertainty 알고리즘**: 1차 교회 주소가 불확실(`LOW`/미확정)하거나 사이트 내 주소 불일치 시, 홈페이지 신뢰도를 무조건 `LOW (검증 보류)`로 강제 강등
  - 1차 주소 확정 및 사이트 내 주소 일치 시에만 `HIGH (확정)` 부여
- [ ] 대화형 Grounding 검증 뷰:
  - 후보 도로명 주소, 우편번호, 포털 지도 바로가기 버튼 표시
  - 후보 홈페이지 URL, 사이트 미리보기 링크, "주소 불확실에 따른 홈페이지 검증 보류" 상태 배지 표시
  - `[원클릭 승인]`, `[주소/URL 직접 수정]`, `[보류]` 및 주소 수기 수정 시 [홈페이지 즉시 재평가] 연계 처리

### Phase 4: 지역별 교세·교단·규모 분석 엔진 & 시각화 (User Requirements)

     - 🔵 **중형 교회**: 100명 ~ 500명 미만
     - 🟡 **중대형 교회**: 500명 ~ 1,000명 미만
     - 🟠 **대형 교회**: 1,000명 ~ 3,000명 미만
     - 🔴 **초대형 교회**: 3,000명 이상
     - *(성도 수 누락 교회: '규모 미입력' 카테고리)*
  4. **규모별 교회 수 및 분포도(Distribution)**:
     - 각 규모 구간별 교회 수(개) 및 비율(%) 산출
     - 교단 × 규모 교차 집계표 (Cross-tabulation)
