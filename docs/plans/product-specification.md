> **문서 버전:** v1.1.0  
> **작성일:** 2026-09-09 (개정일: 2026-09-10)  
> **상태:** 기획 확정 (Approved)

## 1. 서비스 정의 및 기획 배경 (Overview & Purpose)

### 1.1 기획 배경
* **주소 확인의 비효율 및 발송 사고 위험**:
  * 교회 대상 공문이나 선물(명절, 창립기념 등) 발송 요청 시, 주소가 누락되거나 과거 주소인 경우가 많음.
  * 담임목사 성함, 교회명, 지역만 알고 있는 상태에서 포털 검색을 일일이 수행하여 주소를 찾는 작업은 시간 소모가 크고, 동명 교회로 인한 오발송 위험이 상존함.
* **사용자 그룹별 요구 데이터의 격차 (내부 관리 vs 외부 활용)**:
  * **내부 기획자/운영자**: 제안사업 파이프라인, 후속조치, 관리등급, 옵시디언 연계 등 17개 헤더 컬럼의 고도화된 마스터시트 관리가 필수적임.
  * **외부/타 부서 일반 사용자**: 복잡한 제안사업이나 옵시디언 컬럼은 전혀 필요 없으며, 단순히 `[담임목사, 지역, 교회명]` 3개만 넣으면 정제된 **주소록과 공식 홈페이지**만 깔끔하게 산출되기를 원함.
* **이원화된 데이터의 괴리**:
  * 내부 기획자의 경우 업무 현황은 **구글 스프레드시트(엑셀)**로 관리하고, 목회자 성향 및 미팅 히스토리는 **옵시디언(Obsidian)**으로 관리하고 있어 상호 유기적 동기화가 필요함.
* **홈페이지 검증의 주소 종속성**:
  * 교회 홈페이지는 포털 검색만으로는 동명 교회 웹사이트나 엉뚱한 블로그가 잡힐 위험이 높음.
  * 홈페이지 진위는 '교회 실제 주소'를 대조하여 검증하므로, 주소가 불확실하면 홈페이지 역시 필연적으로 불확실로 종속 처리되는 엄격한 검증 체계가 요구됨.

### 1.2 핵심 가치 (Core Value Proposition)
1. **이원화된 운영 모드 (Two-Track Modes)**:
   - **마스터 관리 모드 (내부 운영자용)**: 17개 컬럼 마스터시트 보존 + 교세 분석 + 옵시디언 풀 동기화.
   - **간편 주소록 모드 (외부/일반 사용자용)**: `[담임목사, 지역, 교회명]` 3개 입력 ➡️ `[주소록 + 홈페이지]` 자동 산출 및 간이 엑셀 내보내기.
2. **신뢰할 수 있는 2단계 주소·홈페이지 연계 추정 (Cascading Grounding Intelligence)**:
   - 1차 도로명 주소 추정 및 신뢰도 판정 ➡️ 2차 주소 기반 홈페이지 교차 검증.
   - **주소 불확실 시 홈페이지 자동 불확실 종속 처리**로 오정보 완벽 차단.
3. **원클릭 발송 지원 (Quick Dispatch)**: 공문/택배 규격에 맞춘 텍스트를 초성 검색 후 1초 만에 클립보드로 복사.
4. **지역별 교세 인텔리전스**: 지역별 교단 현황, 총 교회 수, 5단계 성도 수 규모 분포 및 교차 분석 제공.
5. **유기적 데이터 동기화**: 엑셀 ↔ 옵시디언 간 데이터 불일치(Diff) 해소 및 신규 교회 템플릿 자동 보완.

## 2. 사용자 페르소나 및 유저 저니 (User Journey)

### 2.1 주요 페르소나
* **페르소나 A (파워 유저 / 내부 기획자 본인)**:
  * 구글 스프레드시트 마스터시트와 옵시디언 사역 일지를 모두 적극적으로 활용.
  * 17개 기본 컬럼(제안사업, 후속조치, 교세 등) 유지 ➡️ 주소/홈페이지 추정 ➡️ 옵시디언 교회 문서(`20. Churches`) 자동 생성 및 Diff 동기화까지 풀사이클로 사용.
* **페르소나 B (팀원 / 본부 행정 실무자)**:
  * 옵시디언은 사용하지 않음.
  * 내부 마스터시트 엑셀 파일을 업로드하여 주소/홈페이지 일괄 검증 또는 특정 교회 공문/선물 발송 정보를 급히 복사하여 회사 양식에 전달.
* **페르소나 C (외부 사용자 / 타 부서 일반 실무자 - 신규)**:
  * 17개 관리 항목(제안사업, 관리등급 등)이 전혀 불필요하며 존재도 알지 못함.
  * 자신이 가진 단순 목록(`[담임목사, 지역, 교회명]`)만 입력하여, 오직 **도로명 주소와 공식 홈페이지 URL이 포함된 정제된 간편 주소록**을 손쉽게 얻고자 함.

### 2.2 핵심 유저 시나리오 (User Scenarios)

#### 시나리오 1: 마스터시트 주소/홈페이지 일괄 추정 및 승인 (내부용)
1. 기획자가 구글 스프레드시트에서 내려받은 17개 컬럼의 `master.xlsx`를 드롭존에 업로드.
2. 시스템이 주소/홈페이지 누락 교회를 감지하고 [추정 및 검증 시작] 활성화.
3. 백그라운드 탐색 진행 후, **[주소 신뢰도 95% / 목회자 일치 / 네이버 지도 링크 / 홈페이지 주소 일치 확인]** 검증 카드 표출.
4. 사용자가 확인 후 `[승인]` 클릭 시 엑셀 내 `교회 주소`, `우편번호`, `홈페이지`가 원본 서식을 해치지 않고 업데이트.

#### 시나리오 2: 회사 공문/선물 발송 긴급 요청 대응
1. 타 부서에서 "광주 겨자씨교회 담임목사님이랑 주소 좀 급히 알려주세요" 메신저 요청.
2. 사용자가 프로그램의 [공문/선물 퀵서처] 탭에서 `ㄱㅈㅅ` 검색.
3. 즉시 매칭된 카드가 뜨고, `[공문용 복사]` 버튼 클릭.
4. 클립보드에 `수신: 광주겨자씨교회 (나학수 목사 귀하) / 주소: (61642) 광주 남구 봉선로...`가 복사되어 메신저에 바로 붙여넣기 전송.

#### 시나리오 3: 지역별 교세 현황 파악 및 사역 보고
1. [지역별 교세 분석] 탭 클릭.
2. '광주' 지역 선택 시: 총 24개 교회 중 예장합동 12개, 예장통합 8개 등 교단 구성비 차트 표출.
3. 성도 수 기준 소형(~100) 4개, 중형(100~500) 10개, 중대형(500~1000) 5개, 대형(1000~3000) 3개, 초대형(3000~) 2개 집계 확인.
4. '대형' 세그먼트를 클릭하면 해당 3개 교회의 상세 정보 목록이 하단에 즉시 필터링되어 출력.

#### 시나리오 4: 외부 사용자 간편 주소록 & 홈페이지 생성 (신규)
1. 외부 사용자가 앱 실행 시 **[간편 주소록 모드]**를 선택하거나 `[담임목사, 지역, 교회명]` 3개 열로 구성된 단순 엑셀/CSV 파일을 업로드.
2. 시스템이 3개 필수 헤더를 자동 매핑하고 [주소 및 홈페이지 생성] 실행.
3. **1단계 주소 추정 ➡️ 2단계 주소 기반 홈페이지 종속 검증**:
   - 주소가 확실(High)하게 매칭된 교회: 검색된 홈페이지의 '오시는 길' 주소와 일치 확인 시 홈페이지도 '확정(High)' 부여.
   - **주소가 불확실(Low / 미확정)한 교회: 교회 주소를 확정할 수 없으므로, 매칭된 홈페이지도 자동으로 '불확실(Uncertain / 주소 미확정 종속)' 처리하여 오정보 차단.**
4. 검증 완료 후, `[교회명, 담임목사, 지역, 도로명 주소, 우편번호, 교회 홈페이지, 검증 상태]` 7개 컬럼의 간편 주소록 엑셀(`.xlsx`/`.csv`)을 원클릭 다운로드.

## 4. 운영 및 데이터 비즈니스 정책 (Business Policies)

### 4.1 주소 및 홈페이지 연계 신뢰도 판정 정책 (Cascading Grounding Policy)

#### 1. 주소 신뢰도 판정 기준 (Confidence Score)
* **High (90% 이상)**: 검색 결과의 교회명이 입력 교회명과 90% 이상 일치 + 해당 지역(시/군/구) 일치 + 대표자(목회자) 성함이 웹 스니펫에서 교차 확인된 경우.
* **Medium (70% ~ 89%)**: 교회명과 지역은 명확히 일치하나, 목회자 성함이 웹에 노출되지 않거나 복수의 지교회가 존재하는 경우.
* **Low (70% 미만)**: 동일 교회명이 전국에 다수 존재하거나 지역 정보와 모호하게 겹치는 경우.

#### 2. 홈페이지 검증 및 종속적 불확실성 (Cascading Uncertainty) 원칙
교회 홈페이지의 진위 판정은 웹 탐색 결과에 기재된 교회 도로명 주소와의 교차 검증(Cross-validation)을 전제로 한다.
* **원칙 1 (주소 종속성)**: **교회 주소가 불확실(`Low` 또는 미확정)하면, 해당 주소를 기반으로 검증해야 하는 홈페이지 역시 당연히 '불확실(`Uncertain` / `Low`)'로 종속 처리한다.**
  * 주소가 확정되지 않은 상태에서 검색된 URL은 아무리 도메인이 유사하더라도 "주소 미확정에 따른 홈페이지 검증 보류" 상태로 유지하며, 자동으로 신뢰할 수 있는 홈페이지로 채택하지 않는다.
* **원칙 2 (2단계 순차 검증 파이프라인)**:
  1. `1단계 (주소 검증)`: `[지역 + 교회명 + 목회자]`로 도로명 주소 확정.
  2. `2단계 (홈페이지 대조)`: 후보 웹사이트의 '오시는 길' 또는 푸터 주소를 수집하여 1단계 확정 주소와 일치 여부 대조.
     - 주소 일치 + 목회자명 일치 ➡️ `홈페이지 High (확정)`
     - 주소 일치하나 목회자명 미확인 ➡️ `홈페이지 Medium`
     - 주소 불일치 또는 1단계 주소 자체가 불확실 ➡️ **`홈페이지 Low (불확실 / 보류)`**
* **원칙 3 (수기 보정 후 재평가)**:
  * 사용자가 검증 스튜디오에서 주소를 직접 수정하거나 확정하면, 그 즉시 해당 확정 주소를 기준으로 [홈페이지 재검증]을 재호출할 수 있다.

### 4.2 이원화된 데이터 스키마 및 보호 정책 (Dual-Track Schema)

#### 1. 마스터 관리 모드 (내부 기획자용)
* **목적**: 기획자 본인의 파트너십 종합 관리 및 옵시디언 동기화.
* **컬럼 구조**: 기존 17개 고유 헤더 컬럼 100% 보존.
  * `[지역, 구분, 교회명, 담임목사, 교회 주소, 교단, 성도 수(명), 관리등급, 온도감, 관리유형, 1차 제안사업, 1차 제안일, 현재 제안단계, 후속 제안사업, 다음 액션, 다음 접촉일, 비고]`
* **시스템 자동 추가 컬럼**: `우편번호`, `홈페이지`, `주소검증상태`, `홈페이지검증상태`, `Obsidian링크`.
* **보호 원칙**: 프로그램은 임의로 기존 셀의 값을 변경하지 않으며, 임시 파일 원자적 교체(Atomic Replacement)로 엑셀 수식/서식을 완벽 보존.

#### 2. 간편 주소록 모드 (외부/타 부서 일반 사용자용)
* **목적**: 복잡한 사역/관리 항목 없이, 단순 목록에서 신속하게 정제된 주소록 및 홈페이지 링크 생성.
* **필수 입력 (3개)**: `[담임목사, 지역, 교회명]` (순서 무관 자동 인식, 그 외 헤더 무시)
* **산출 결과 (간편 주소록 7개 컬럼)**:
  * `[교회명, 담임목사, 지역, 도로명 주소, 우편번호, 교회 홈페이지, 검증 상태]`
* **외부 내보내기**: 불필요한 사내 관리용 컬럼(제안사업, 온도감 등)이 완전히 배제된 깔끔한 간편 주소록 파일(`.xlsx` / `.csv`)로 즉시 내보내기 지원.

### 4.3 교세(성도 수) 5단계 분류 정책
* 사용자가 지정한 5대 세그먼트를 엄격히 준수:
  1. **소형 교회**: 100명 미만
  2. **중형 교회**: 100명 이상 ~ 500명 미만
  3. **중대형 교회**: 500명 이상 ~ 1,000명 미만
  4. **대형 교회**: 1,000명 이상 ~ 3,000명 미만
  5. **초대형 교회**: 3,000명 이상
* `성도 수(명)` 값이 비어있거나 텍스트로 기재된 경우 '규모 미입력' 그룹으로 분리하여 데이터 보완 대상으로 유도.

### 4.4 옵시디언 동기화 및 충돌 해결 정책
* **식별 키**: `교회명`을 기본 키로 하되, 동명 교회의 경우 `지역 + 교회명`으로 유니크성 확보.
* **Diff 발생 시**: 프로그램이 일방적으로 덮어쓰지 않고 반드시 사용자에게 [엑셀 기준 반영] vs [옵시디언 기준 반영] 선택지를 제공.
* **템플릿 준수**: 신규 노트 생성 시 기존 `Template - Church (교회_조직).md` 구조를 완벽하게 유지.
