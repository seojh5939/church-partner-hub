# 📋 [기획안] church-partner-hub (교회 파트너십 허브) 서비스 기획안

> **문서 버전:** v1.0.0  
> **작성일:** 2026-09-09  
> **상태:** 기획 확정 (Approved)  
> **대상:** 기아대책 파트너십 담당자, 본부/팀 실무자

## 1. 서비스 정의 및 기획 배경 (Overview & Purpose)

### 1.1 기획 배경
* **주소 확인의 비효율 및 발송 사고 위험**:
  * 교회 대상 공문이나 선물(명절, 창립기념 등) 발송 요청 시, 주소가 누락되거나 과거 주소인 경우가 많음.
  * 담임목사 성함, 교회명, 지역만 알고 있는 상태에서 포털 검색을 일일이 수행하여 주소를 찾는 작업은 시간 소모가 크고, 동명 교회로 인한 오발송 위험이 상존함.
* **이원화된 데이터의 괴리**:
  * 업무 현황 및 제안사업 파이프라인은 **구글 스프레드시트(엑셀)**로 관리하고, 목회자 성향 및 미팅 히스토리는 **옵시디언(Obsidian)**으로 관리하고 있으나, 두 도구 간 데이터가 유기적으로 연결되지 못함.
* **조직 내 활용성(범용성) 필요**:
  * 개인의 옵시디언 환경뿐만 아니라, 옵시디언을 쓰지 않는 팀원/본부 직원도 엑셀 파일만으로 즉시 주소를 찾고 교세를 파악할 수 있는 독립형 도구가 필요함.

### 1.2 핵심 가치 (Core Value Proposition)
1. **신뢰할 수 있는 주소 추정 (Grounding Intelligence)**: 단순 자동 입력이 아닌, 지도 링크 및 목회자 일치 근거를 사람이 직접 확인하고 승인하는 체계.
2. **원클릭 발송 지원 (Quick Dispatch)**: 공문/택배 규격에 맞춘 텍스트를 초성 검색 후 1초 만에 클립보드로 복사.
3. **지역별 교세 인텔리전스**: 지역별 교단 현황, 총 교회 수, 5단계 성도 수 규모 분포 및 교차 분석 제공.
4. **유기적 데이터 동기화**: 엑셀 ↔ 옵시디언 간 데이터 불일치(Diff) 해소 및 신규 교회 템플릿 자동 보완.

## 2. 사용자 페르소나 및 유저 저니 (User Journey)

### 2.1 주요 페르소나
* **페르소나 A (파워 유저 / 기획자 본인)**:
  * 구글 스프레드시트 마스터시트와 옵시디언 사역 일지를 모두 적극적으로 활용.
  * 주소 추정 ➡️ 엑셀 반영 ➡️ 옵시디언 교회 문서(`20. Churches`) 자동 생성 및 Diff 동기화까지 풀사이클로 사용.
* **페르소나 B (팀원 / 본부 행정 실무자)**:
  * 옵시디언은 사용하지 않음.
  * 엑셀 파일을 프로그램에 넣고 주소가 누락된 교회들의 주소를 일괄 추정/검증하여 완성된 엑셀을 다운로드받거나, 특정 교회 선물 발송 정보를 급히 복사하여 회사 양식에 넘겨주는 용도로 사용.

### 2.2 핵심 유저 시나리오 (User Scenarios)

#### 시나리오 1: 주소 누락 교회 일괄 추정 및 승인
1. 사용자가 프로그램 실행 후 구글 스프레드시트에서 내려받은 `master.xlsx`를 드롭존에 업로드.
2. 시스템이 `교회 주소`가 누락된 15개 교회를 감지하고 [주소 추정 시작] 활성화.
3. 백그라운드 탐색 진행 후, 화면에 **[신뢰도 95% / 목회자 일치 확인 / 네이버 지도 링크]**가 포함된 검증 카드가 뜸.
4. 사용자가 지도 링크를 눌러 확인 후 `[승인]` 버튼을 클릭.
5. 엑셀의 `교회 주소` 및 `우편번호`가 자동 업데이트되고, 업데이트된 엑셀 파일을 즉시 다운로드하거나 저장.

#### 시나리오 2: 회사 공문/선물 발송 긴급 요청 대응
1. 타 부서에서 "광주 겨자씨교회 담임목사님이랑 주소 좀 급히 알려주세요" 메신저 요청.
2. 사용자가 프로그램의 [공문/선물 퀵서처] 탭에서 `ㄱㅈㅅ` 검색.
3. 즉시 매칭된 카드가 뜨고, `[공문용 복사]` 버튼 클릭.
4. 클립보드에 `수신: 광주겨자씨교회 (나학수 목사 귀하) / 주소: (61642) 광주 남구 봉선로...`가 복사되어 메신저에 바로 붙여넣기 전송.

#### 시나리오 3: 지역별 교세 현황 파악 및 사역 보고
1. [지역별 교세 분석] 탭 클릭.
2. '광주' 지역 선택 시: 총 24개 교회 중 예장합동 12개, 예장통합 8개 등 교단 구성비 차트 표출.
3. 성도 수 기준 소형(~100) 4개, 중형(100~500) 10개, 중대형(500~1000) 5개, 대형(1000~3000) 3개, 초대형(3000~) 2개 집계 확인.
4. '대형' 세그먼트를 클릭하면 해당 3개 교회의 상세 정보 목록이 하단에 즉시 필터링되어 출력.

## 4. 운영 및 데이터 비즈니스 정책 (Business Policies)

### 4.1 주소 신뢰도 판정 및 Grounding 정책
* **판정 기준 (Confidence Score)**:
  * **High (90% 이상)**: 검색 결과의 교회명이 입력 교회명과 90% 이상 일치 + 해당 지역(시/군/구) 일치 + 대표자(목회자) 성함이 웹 스니펫에서 교차 확인된 경우.
  * **Medium (70% ~ 89%)**: 교회명과 지역은 명확히 일치하나, 목회자 성함이 웹에 노출되지 않거나 복수의 지교회가 존재하는 경우.
  * **Low (70% 미만)**: 동일 교회명이 전국에 다수 존재하거나 지역 정보와 모호하게 겹치는 경우.
* **승인 원칙**:
  * High 등급이라도 최종 저장은 사용자의 확인(원클릭 승인)을 거침을 원칙으로 함.
  * 사용자가 승인한 주소는 `주소검증상태 = '승인완료'`로 태깅되어 재검색 대상에서 제외.

### 4.2 엑셀 마스터시트 17개 컬럼 보호 정책
* 기본 17개 컬럼 순서 및 서식은 원본 구글 스프레드시트 구조를 100% 보존.
* 프로그램은 오직 `교회 주소` 및 신규 시스템 컬럼(`우편번호`, `주소검증상태`, `Obsidian링크`)만 안전하게 업데이트하며, 사용자가 직접 수정한 비고나 후속조치 내역을 임의로 덮어쓰지 않음.
* 엑셀 파일 쓰기 시 임시 파일 생성 후 원자적 교체(Atomic Replacement)를 수행하여 파일 손상 방지.

### 4.3 교세(성도 수) 5단계 분류 정책
* 사용자가 지정한 5대 세그먼트를 엄격히 준수:
  1. **소형 교회**: 100명 미만
  2. **중형 교회**: 100명 이상 ~ 500명 미만
  3. **중대형 교회**: 500명 이상 ~ 1,000명 미만
  4. **대형 교회**: 1,000명 이상 ~ 3,000명 미만
  5. **초대형 교회**: 3,000명 이상
* `성도 수(명)` 값이 비어있거나 텍스트로 기재된 경우 '규모 미입력' 그룹으로 분리하여 데이터 보완 대상으로 유도.

### 4.4 옵시디언 동기화 및 충돌 해결 정책
* **식별 키**: `교회명`을 기본 키로 하되, 동명 교회의 경우 `지역 + 교회명`으로 유니크성 확보.
* **Diff 발생 시**: 프로그램이 일방적으로 덮어쓰지 않고 반드시 사용자에게 [엑셀 기준 반영] vs [옵시디언 기준 반영] 선택지를 제공.
* **템플릿 준수**: 신규 노트 생성 시 기존 `Template - Church (교회_조직).md` 구조를 완벽하게 유지.
